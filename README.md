# Asteroids

Небольшая браузерная игра для курса AIDev. Исходный код создан для этого
репозитория и распространяется по лицензии MIT.

## Запуск

Нужны Node.js 24 и npm. На Windows используйте WSL либо Node.js для Windows.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. Сервер слушает только локальную машину.
←/→ или A/D — поворот, ↑ или W — тяга, пробел — стрельба, P — пауза.
Три жизни; после столкновения действует короткая неуязвимость.
Большой астероид распадается на два средних, средний — на два маленьких.

Миссии задают разные цели:

- **Первый вылет:** уничтожьте три медленных астероида вместе с осколками.
  После одной очищенной волны появляется экран победы.
- **Плотный пояс:** продержитесь 60 секунд в пополняющемся потоке справа налево.
  Цель и оставшееся время видны над полем; пауза останавливает таймер.
- **Барби: курс на Дримхаус:** соберите три сердца, переживите 20 секунд
  диско-шторма с лазерами и войдите в портал. На всё 90 секунд.
  Сердца дают щит и тройной залп, Shift включает защитный рывок.
  Прямая ссылка после запуска: `/?mission=barbie-dream-orbit`.
- **Солнечная мельница:** короткий, но плотный поток на 45 секунд — двенадцать
  быстрых астероидов и пополнение каждые 0,75 секунды.
- **Скоростной коридор:** продержитесь 45 секунд в ускоренном потоке.
  Десять начальных астероидов, двойная базовая скорость и пополнение каждые
  0,75 секунды делают этот вылет сложнее «Плотного пояса».

После завершения можно повторить миссию или выбрать другую.
Старые JSON без поля mode сохраняют бесконечные волны.

## Проверка

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm run check` объединяет модульные тесты и сборку.
Браузерные тесты сами запускают и останавливают сервер на порту 4173.
На Linux для браузера могут понадобиться системные библиотеки:
`npx playwright install --with-deps chromium`.

## Устройство

Симуляция находится в `src/game/` и не зависит от браузера.
[Контракт](docs/game-core.md) описывает состояние и единицы измерения.
Браузерный адаптер `src/main.js` связывает ввод и HUD с симуляцией;
`src/render.js` рисует поле. Проверки интерфейса используют управляемые
сцены в режиме Vite `test`. В production-сборке тестовый доступ к состоянию
отсутствует.

## Работа с агентом

Из корня репозитория запустите выбранный клиент:

```sh
codex
# либо
claude --permission-mode auto
```

После доверия проекту Codex использует Auto-review: запросы дополнительного
доступа оценивает отдельный агент при сохранении workspace-write.
В Claude Code Auto выбирается флагом запуска; проектные settings не могут
включить этот режим.

Codex prompt обращается к активному ревьюеру, а Claude Code ask сохраняет
ручное подтверждение. Права GitHub и одобрение PR проверяются отдельно.
[Подробности, проверка загрузки и ручной режим](docs/agent-setup.md).

## Вклад в проект

Для контрибьюта создайте личный форк. Приглашение в организацию не нужно.
Нужен [GitHub CLI](https://cli.github.com/) с выполненным `gh auth login`.
Из папки, где хотите разместить проект, выполните:

```sh
gh repo fork asteroids-developers/asteroids --clone --remote
```

Команда создаст форк в вашем аккаунте, склонирует его в папку `asteroids`
и настроит remotes: `origin` — ваш форк, `upstream` — общий репозиторий.
Создайте рабочую ветку от актуальной общей версии:

```sh
cd asteroids
git fetch upstream
git switch -c feat/my-mission upstream/main
```

Если общий репозиторий уже склонирован, выполните в нём
`gh repo fork --remote`: GitHub CLI подключит личный форк к существующей папке.

После коммита и push своей ветки откройте PR в общую `main`:

```sh
git push -u origin feat/my-mission
gh pr create --repo asteroids-developers/asteroids --base main
```

Ветки отправляются в ваш форк: публичность общего репозитория не даёт права
push в него. Для слияния PR нужны зелёный CI и одобрение `@KalininVD`.
Его собственные PR допускают обход только требования ревью; CI обязателен
для всех. Подробности и разрешение конфликтов — в [CONTRIBUTING.md](CONTRIBUTING.md).

Миссии задаются отдельными JSON-файлами и автоматически появляются в меню.
[Добавление миссии](docs/missions.md) — небольшая самостоятельная задача для PR.
В репозитории есть стартовые настройки Codex и Claude Code.
[Как их проверить](docs/agent-setup.md),
[готовые MCP и plugins](docs/mcp-and-plugins.md),
[правила участия и разрешение конфликтов](CONTRIBUTING.md).

Актуальное сравнение: теги `workshop-2026-09-28-configured` и
`workshop-2026-09-28-control` содержат одинаковую игру с агентскими
настройками и без них. Ветка `control` хранит контрольный вариант.
Старый `workshop-start` сохранён как исторический снимок с настройками.
